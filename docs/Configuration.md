# 工作区配置

配置位于工作区根目录的 `config.json`，版本为 `1`。可从设置中的工作流、捕获模板、文件与议程和提醒页面编辑，也可在「配置文件」导入 JSON。示例见 [config.example.json](config.example.json)。

## 保存与恢复

工作区设置修改后自动写入本机，再随工作区同步，无需保存或完成按钮。连续输入会短暂合并写入；状态和模板使用原生列表排序控件，把手始终显示在行末，可直接拖动。长按状态可移动分组或删除。输入无效或保存失败会保留修改；返回时会先处理待保存的修改，失败时可以继续编辑、重试保存或放弃。本机外观与通知开关立即生效，不写入工作区配置。

「经典工作流预设」只替换 `workflow`，不会修改文件位置、模板、议程来源、历史记录或提醒规则。确认重置默认配置或导入后，会替换整个配置并自动保存。保存替换后，可在同一页撤销；后续保存、重新载入或工作区配置在其他位置发生变化后，旧的撤销快照失效，以免覆盖新修改。

## 字段与路径

- `workflow`：一个默认状态序列，包括进行中、结束状态及新任务、完成、重开默认状态。状态可设置显示名称、快捷选择键、内置图标、颜色和进入／离开日志规则。文件内的 `#+TODO` 声明优先于工作区默认值。
- `files`：收件箱、附件目录、年度日记目录、归档规则和移动目标。普通路径相对工作区根目录，不允许绝对路径或 `..`。归档规则使用 `相对文件::标题`；`%s` 代表原文件名，归档路径相对原文件所在目录。例如 `work/tasks.org` 使用 `%s_archive::* Archived` 时归档到 `work/tasks.org_archive`。
- `agenda`：包含和排除的文件或目录；目录包含子目录。包含列表为空时使用全部可见 Org 文件。排除规则优先，隐藏目录、归档及恢复文件不会进入议程。设置页展示当前已加载文件的匹配预览。
- `capture`：默认模板及模板列表。目标支持文件、标题、标题路径或日期树，模板正文直接使用 Org 文本。可先试用模板，再保存；试用不写入文件。模板中的 `%?`、`%^{Title}`、`%U`、`%t` 分别表示光标文本、输入问题、时间戳和活动日期。不执行 Lisp 或脚本。
- `logging`：完成、改期和更改截止日期时的记录规则，值为 `none`、`time` 或 `note`。抽屉名称留空时写入正文。
- `reminders`：提前提醒分钟数 `0–1440`、重复间隔 `1–1440` 分钟和议程截止日期预览 `0–365` 天。重复提醒在条目开始时结束；默认在提前 15、10、5 分钟及开始时提醒。实际发送还需要本机启用和系统授权，条目自己的提前提醒时间优先。截止日期预览不会发送通知。

缺省对象字段使用默认值；数组会替换默认数组。未知字段会保留并给出提示，不会执行。应用主题、标签与优先级样式、Dashboard 布局和应用快捷键不通过此文件定制。

## 从 Emacs 迁移

在「从 Emacs 提取」复制转换提示词，交给所选助手并提供需要转换的 Emacs 配置。检查其转换报告，确认不支持的功能和未解析的值。随后仅将检查过的 JSON 文件导入或粘贴到「配置文件」，验证通过后自动保存。Orgenda 不会上传或执行 Emacs 配置，也不会因导入而改写已有 Org 文件。
